## 🔴 Critical Bugs

### 1. Race Condition in `subscribeWithNC` Transaction
**File**: `src/services/subscriptionService.ts`

**Issue**: The subscription existence check happens outside the `runTransaction` callback, creating a race condition where concurrent subscription attempts could both pass the initial check and attempt to create duplicate subscriptions.

```typescript
// Current code - check happens BEFORE transaction
const existingSubSnap = await getDocs(query(...)); // ❌ Outside transaction
if (!existingSubSnap.empty) throw new Error("ACTIVE_SUB_EXISTS");

return runTransaction(db, async tx => { // ❌ Too late to prevent race
  // ...
});
```

**Impact**: Users could be charged twice or have duplicate subscription records.

**Fix**: Move the existence check inside the transaction:
```typescript
return runTransaction(db, async tx => {
  // Check inside transaction for atomicity
  const existingSubSnap = await tx.get(subRef);
  if (existingSubSnap.exists()) {
    const existing = existingSubSnap.data() as Subscription;
    const end = toDate(existing.currentPeriodEnd);
    if (end && end > new Date()) {
      throw new Error("ACTIVE_SUB_EXISTS");
    }
  }
  // ... rest of transaction
});

### 3. Incorrect User Document Query in Fallback
**File**: `src/services/subscriptionService.ts`

**Issue**: Uses unusual query pattern for fetching user document:

const userSnap = await getDocs(

**Impact**: May not work as expected; inefficient compared to direct document fetch.

## 🟡 Medium Severity Bugs

### 4. Inconsistent Status Computation Logic
**File**: `src/services/subscriptionService.ts`, `computeSubState` function

**Issue**: Trial subscriptions could theoretically continue past their 30-day intended duration if the status field isn't properly updated, as the function relies on the stored `status` field rather than recalculating based on dates.

**Fix**: Add explicit validation that trial periods cannot exceed their intended duration regardless of stored status.

### 5. Missing Audit Logging for Subscription Mutations
**File**: `src/services/subscriptionService.ts`

**Issue**: While the spec requires audit logging for actions like `subscription_purchased`, `subscription_cancelled`, etc., the actual service functions don't write to the audit log.

**Impact**: No audit trail for subscription changes, hindering fraud detection and troubleshooting.

**Fix**: Integrate `auditService.logAudit()` calls in all subscription mutation functions.

### 6. Hardcoded Plan IDs Create Maintenance Risk
**File**: `src/services/subscriptionService.ts`

**Issue**: `PAID_PLAN_IDS` array is hardcoded separately from `SUB_PLANS`:
```typescript
const PAID_PLAN_IDS: [PlanId, ...PlanId[]] = [
  "business_3m_v1", "business_6m_v1", "business_12m_v1",
];
```

**Impact**: Adding new plans requires updating two places, creating risk of validation bugs.

**Fix**: Derive programmatically:
```typescript
const PAID_PLAN_IDS = SUB_PLANS.map(p => p.id) as [PlanId, ...PlanId[]];
```
