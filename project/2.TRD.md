## 5. Security Implementation

### 5.1 Firestore Security Rules (Excerpt)
```javascript
// Allow read/write only if user is authenticated and owns the document
match /users/{userId} {
  allow read: if request.auth != null;
  allow write: if request.auth != null && request.auth.uid == userId;
  
  // Public profile subcollection - readable by all authenticated users
  match /publicProfile/{profileId} {
    allow read: if request.auth != null;
    allow write: if request.auth != null && request.auth.uid == userId;
  }
}

// Bookings: only participants and admins can access
match /bookings/{bookingId} {
  allow read: if request.auth != null && (
    resource.data.residentId == request.auth.uid ||
    resource.data.professionalId == request.auth.uid ||
    isAdmin(request.auth.uid, resource.data.societyId)
  );
  allow write: if false; // Only via Cloud Functions
}
```

### 5.2 Cloud Functions Security
- All endpoints validate Firebase ID token via `admin.auth().verifyIdToken()`
- Role-based authorization checks on every protected endpoint
- Input validation using Zod schemas before processing
- Rate limiting via Firebase Extensions or custom middleware
- Webhook endpoints verify Razorpay signature using HMAC-SHA256

### 5.3 Data Protection
- PII fields encrypted at application layer before Firestore write
- File uploads scanned for malware via Cloudinary API
- Audit logs for all admin actions and financial transactions
- Data retention policies: soft-delete with 90-day recovery window

## 6. Performance & Scalability

### 6.1 Frontend Optimization
- Code splitting by route via Vite dynamic imports
- Image lazy loading with blur-up placeholders
- TanStack Query stale-time configuration to reduce refetches
- Service Worker caching for static assets (PWA)

### 6.2 Backend Optimization
- Firestore queries limited to 100 documents with pagination cursors
- Cloud Functions timeout: 60s for sync, 540s for async tasks
- Batch writes for bulk operations (max 500 ops/batch)
- Composite indexes for complex queries to avoid collection scans

### 6.3 Caching Strategy
```typescript
// TanStack Query configuration
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 5 * 60 * 1000,    // 5 minutes
      cacheTime: 30 * 60 * 1000,   // 30 minutes
      retry: 1,
      refetchOnWindowFocus: false,
    },
  },
});
```

### 6.4 Monitoring & Alerting
- Sentry DSN configured for frontend error tracking
- Firebase Performance Monitoring for API latency
- Cloud Functions logs shipped to Cloud Logging
- Custom metrics: booking success rate, payment failures, verification throughput

## 10. Technical Debt & Future Considerations

### 10.1 Known Limitations (Phase 1)
- Wallet top-ups disabled on Firebase Spark plan (require Blaze)
- No real-time availability slots (request-based only)
- Limited admin analytics (basic user/booking lists only)
- Single-society isolation (no cross-society discovery)

### 10.2 Scaling Challenges
- Firestore query costs at scale → Consider BigQuery export for analytics
- Cloud Functions cold starts → Keep-warm pings or migrate critical paths
- Image storage costs → Implement lifecycle policies + CDN caching

### 10.3 Architecture Evolution
```
Phase 1: Monolithic Firebase backend
     ↓
Phase 2: Microservices for payments/messaging via Cloud Run
     ↓
Phase 3: Multi-region deployment for global expansion
```
