## 1. Database Architecture Overview

### 1.1 Technology Stack
- **Primary Database**: Firestore (NoSQL, document-oriented)
- **File Storage**: Firebase Storage + Cloudinary proxy for image optimization
- **Search**: Firestore queries with composite indexes (Phase 1); Algolia consideration (Phase 2)
- **Caching**: TanStack Query client-side + Firestore offline persistence
- **Analytics**: Firebase Analytics → BigQuery export for complex queries

### 1.2 Design Principles
- **Denormalization for Read Performance**: Duplicate frequently accessed fields (e.g., `professionalName` in bookings)
- **Collection Group Queries**: Enable cross-collection analytics (e.g., all messages across conversations)
- **Subcollections for Scale**: Use subcollections for high-volume, related data (messages under conversations)
- **Security by Design**: Firestore rules enforce access control at database layer
- **Immutable Audit Trail**: Critical actions logged to append-only `audit_logs` collection

**Access Pattern**: Read-heavy (profile views), moderate writes (profile updates)

### 2.3 `bookings` Collection
**Purpose**: Track service requests, scheduling, and lifecycle  
**Document ID**: Auto-generated (ULID for sortability)  
**Access Pattern**: High write volume (status updates), moderate reads

```typescript
interface BookingDocument {
  id: string;                     // ULID: 01HXYZ... (time-sortable)
  
  // === Participants ===
  residentId: string;             // Reference to users/{uid}, indexed
  professionalId: string;         // Reference to users/{uid}, indexed
  societyId: string;              // Reference to societies/{id}, indexed
  
  // === Service Details ===
  service: {
    category: string;             // Indexed: e.g., "plumbing", "electrical"
    title: string;                // e.g., "Fix leaking kitchen tap"
    description: string;          // Max 1000 chars, sanitized
    duration: number;             // In minutes (e.g., 60)
    price: number;                // In INR (locked at booking time)
    currency: 'INR';
  };
  
  // === Scheduling ===
  requestedAt: Timestamp;         // When resident submitted request
  scheduledFor: Timestamp;        // Start time of service, indexed
  status: BookingStatus;          // Indexed: see state machine below
  location: {
    type: 'home' | 'clubhouse' | 'other';
    address?: string;             // Full address if not home
    instructions?: string;        // e.g., "Gate code: 1234"
  };
  
  // === Payment ===
  payment: {
    status: 'pending' | 'paid' | 'refunded' | 'failed';
    method: 'wallet' | 'razorpay';
    transactionId?: string;       // Razorpay payment ID
    refundedAmount?: number;
    refundedAt?: Timestamp;
  };
  
  // === Communication ===
  conversationId: string;         // Reference to conversations/{id}
  
  // === Timeline & Audit ===
  timeline: Array<{
    status: BookingStatus;
    timestamp: Timestamp;
    updatedBy: string;            // User UID or 'system'
    notes?: string;
  }>;
  
  // === Cancellation & Disputes ===
  cancellation?: {
    requestedBy: 'resident' | 'professional';
    requestedAt: Timestamp;
    reason: string;
    refundAmount: number;
    processedAt?: Timestamp;
  };
  
  dispute?: {
    raisedBy: 'resident' | 'professional';
    raisedAt: Timestamp;
    reason: string;
    status: 'open' | 'resolved' | 'closed';
    resolution?: {
      decidedBy: string;          // Admin UID
      decidedAt: Timestamp;
      action: 'refund' | 'credit' | 'warning' | 'no_action';
      notes: string;
    };
  };
  
  // === Completion & Reviews ===
  completedAt?: Timestamp;
  review?: {
    rating: number;               // 1-5
    comment?: string;
    submittedAt: Timestamp;
    isAnonymous: boolean;
  };
  
  // === Metadata ===
  createdAt: Timestamp;
  updatedAt: Timestamp;           // Updated on every status change
  _v: number;                     // Schema version
}

// Booking Status State Machine
type BookingStatus = 
  | 'draft'           // Client-side only, not persisted
  | 'requested'       // Submitted to professional
  | 'confirmed'       // Professional accepted
  | 'in_progress'     // Service being delivered
  | 'completed'       // Service done, awaiting review
  | 'cancelled'       // Cancelled by either party
  | 'disputed';       // Issue raised, admin review needed
```

```typescript
// functions/src/bookings/onStatusChange.ts
export const onBookingStatusChange = functions.firestore
  .document('bookings/{bookingId}')
  .onUpdate(async (change, context) => {
    const before = change.before.data() as BookingDocument;
    const after = change.after.data() as BookingDocument;
    
    // Only process actual status changes
    if (before.status === after.status) return;
    
    // 1. Add to timeline (immutable audit)
    await change.after.ref.update({
      timeline: admin.firestore.FieldValue.arrayUnion({
        status: after.status,
        timestamp: admin.firestore.FieldValue.serverTimestamp(),
        updatedBy: context.auth?.uid || 'system'
      })
    });
    
    // 2. Trigger notifications based on transition
    await handleStatusNotification(before.status, after.status, after);
    
    // 3. Update aggregated stats (denormalized)
    if (after.status === 'completed') {
      await updateUserStats(after.professionalId, {
        completedBookings: admin.firestore.FieldValue.increment(1),
        lastCompletedAt: admin.firestore.FieldValue.serverTimestamp()
      });
    }
    
    // 4. Log to audit trail for compliance
    await logAuditEvent({
      collection: 'bookings',
      docId: context.params.bookingId,
      action: 'status_change',
      metadata: { from: before.status, to: after.status }
    });
  });
```

**Security Rules for Messaging**:
```javascript
match /conversations/{conversationId} {
  // Only participants can read/write conversation metadata
  allow read, write: if request.auth != null 
                     && request.auth.uid in resource.data.participants;
  
  // Messages subcollection: same participant check
  match /messages/{messageId} {
    allow read: if request.auth != null 
                && request.auth.uid in get(/databases/$(database)/documents/conversations/$(conversationId)).data.participants;
    
    allow create: if request.auth != null 
                  && request.auth.uid in get(/databases/$(database)/documents/conversations/$(conversationId)).data.participants
                  && request.resource.data.senderId == request.auth.uid
                  && !request.resource.data.isDeleted; // Prevent creating already-deleted messages
    
    // Updates only for delivery/read tracking (system or recipient)
    allow update: if request.auth != null 
                  && (request.auth.uid == resource.data.senderId  // Sender can update delivery
                      || request.auth.uid in get(/databases/$(database)/documents/conversations/$(conversationId)).data.participants) // Recipient can mark read
                  && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['deliveredAt', 'readAt']);
    
    // Soft delete: only sender or admin
    allow update: if request.auth != null 
                  && (request.auth.uid == resource.data.senderId || isAdmin(request.auth.uid))
                  && request.resource.data.isDeleted == true
                  && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['isDeleted']);
  }
}
```

### 2.5 `wallet_transactions` Collection
**Purpose**: Immutable ledger for all financial movements  
**Document ID**: Auto-generated (ULID for time-sorting)  
**Access Pattern**: Append-only writes, read-heavy for history views

```typescript
interface WalletTransactionDocument {
  id: string;                     // ULID: time-sortable for ledger views
  
  // === Actor & Context ===
  userId: string;                 // Reference to users/{uid}, indexed
  type: TransactionType;          // Indexed: see enum below
  relatedEntity?: {
    type: 'booking' | 'payout' | 'adjustment';
    id: string;                   // Booking ID, payout ID, etc.
  };
  
  // === Financial Details ===
  amount: number;                 // Positive = credit, negative = debit (in INR)
  currency: 'INR';
  balanceAfter: number;           // Denormalized: user's wallet balance after this tx
  
  // === Payment Gateway Integration ===
  paymentGateway?: {
    provider: 'razorpay';
    orderId?: string;             // Razorpay order ID
    paymentId?: string;           // Razorpay payment ID
    signature?: string;           // For webhook verification
    metadata?: Record<string, any>; // Pass-through from client
  };
  
  // === Status & Audit ===
  status: 'pending' | 'completed' | 'failed' | 'reversed';
  processedAt: Timestamp;         // When transaction was finalized
  failureReason?: string;         // If status === 'failed'
  
  // === Human-Readable Context ===
  description: string;            // e.g., "Booking #BK-123 - Plumbing Service"
  metadata?: {
    bookingId?: string;
    professionalId?: string;
    societyId?: string;
    // ... other contextual fields for reporting
  };
  
  // === Compliance ===
  ipAddress?: string;             // For fraud detection (hashed)
  userAgent?: string;             // Client info for audit
  _v: number;                     // Schema version
}

enum TransactionType {
  // Resident Flows
  WALLET_TOPUP = 'wallet_topup',
  BOOKING_PAYMENT = 'booking_payment',
  REFUND_RECEIVED = 'refund_received',
  
  // Professional Flows
  BOOKING_EARNING = 'booking_earning',    // When booking completes
  PAYOUT_REQUESTED = 'payout_requested',  // When pro requests withdrawal
  PAYOUT_COMPLETED = 'payout_completed',  // When bank transfer succeeds
  PLATFORM_FEE = 'platform_fee',          // Deducted from earnings
  
  // System & Admin
  ADMIN_ADJUSTMENT = 'admin_adjustment',  // Manual credit/debit by admin
  PROMOTION_CREDIT = 'promotion_credit',  // Referral bonus, welcome credit
  REVERSAL = 'reversal';                  // Undo failed transaction
}
```

**Atomic Wallet Update Pattern**:
```typescript
// functions/src/wallet/creditUser.ts
export async function creditUser(userId: string, amount: number, context: TransactionContext): Promise<void> {
  const userRef = db.collection('users').doc(userId);
  const txRef = db.collection('wallet_transactions').doc(); // Pre-generate ID
  
  await db.runTransaction(async (transaction) => {
    // 1. Read current user state
    const userSnap = await transaction.get(userRef);
    if (!userSnap.exists) throw new Error('User not found');
    
    const user = userSnap.data() as UserDocument;
    const newBalance = user.wallet.balance + amount;
    
    // 2. Create transaction record
    const transactionDoc: Partial<WalletTransactionDocument> = {
      userId,
      type: context.type,
      amount,
      currency: 'INR',
      balanceAfter: newBalance,
      status: 'completed',
      description: context.description,
      metadata: context.metadata,
      processedAt: admin.firestore.FieldValue.serverTimestamp(),
      _v: 1
    };
    
    if (context.paymentGateway) {
      transactionDoc.paymentGateway = context.paymentGateway;
    }
    
    // 3. Update user wallet (denormalized balance)
    transaction.update(userRef, {
      'wallet.balance': newBalance,
      updatedAt: admin.firestore.FieldValue.serverTimestamp(),
      // Update aggregated stats if applicable
      ...(context.type === 'booking_earning' && {
        'stats.totalEarned': admin.firestore.FieldValue.increment(amount)
      })
    });
    
    // 4. Write transaction record (immutable)
    transaction.set(txRef, transactionDoc);
  });
}
```

```typescript
  id: string;
  
  // === Event Context ===
  collection: string;             // e.g., "users", "bookings"
  docId: string;                  // Affected document ID
  action: 'create' | 'update' | 'delete' | 'status_change' | 'financial';
  
  // === Actor ===
  actor: {
    uid: string;                  // User who performed action
    role: UserRole;
    ipAddress?: string;           // Hashed for privacy
    userAgent?: string;
  };
  
  // === Change Details ===
  changes?: {                     // For update actions
    before: Record<string, any>;  // Sanitized: no PII
    after: Record<string, any>;
    affectedFields: string[];
  };
  
  // === Financial Specific ===
  financial?: {
    transactionId: string;        // Reference to wallet_transactions
    amount: number;
    type: TransactionType;
  };
  
  // === Compliance ===
  timestamp: Timestamp;           // Server timestamp
  reason?: string;                // For admin-initiated actions
  approvedBy?: string;            // For sensitive actions requiring dual approval
  
  // === Metadata ===
  _v: number;
  // Note: This collection is WRITE-ONLY after creation (no updates/deletes)
}
```

**Security Rules for Audit Logs**:
```javascript
match /audit_logs/{logId} {
```

## 4. Data Migration & Versioning Strategy

### 4.1 Schema Versioning
- Every document includes `_v: number` field (starts at 1)
- Cloud Functions check version on read and auto-migrate if needed
- Migration scripts stored in `/scripts/migrations/` with rollback capability

### 4.2 Example Migration: Adding Wallet to Existing Users
```typescript
// scripts/migrations/20260514_add_wallet_to_users.ts
export async function migrateUsersToAddWallet(): Promise<void> {
  const usersRef = collection(db, 'users');
  const snapshot = await getDocs(query(
    usersRef,
    where('_v', '<', 2), // Only migrate old schema
    where('role', 'in', ['resident', 'professional'])
  ));
  
  const batch = db.batch();
  let count = 0;
  
  for (const doc of snapshot.docs) {
    const userData = doc.data() as UserDocument;
    
    // Add wallet field with default balance
    batch.update(doc.ref, {
      wallet: {
        balance: 0,
        currency: 'INR',
        ...(userData.role === 'professional' && {
          totalEarned: 0,
          pendingPayout: 0
        }),
        ...(userData.role === 'resident' && {
          totalSpent: 0
        })
      },
      _v: 2, // Increment schema version
      updatedAt: FieldValue.serverTimestamp()
    });
    
    count++;
    // Batch limit: 500 operations
    if (count % 500 === 0) {
      await batch.commit();
      console.log(`Migrated ${count} users...`);
    }
  }
  
  // Commit remaining
  if (count % 500 !== 0) {
    await batch.commit();
  }
  
  console.log(`Migration complete: ${count} users updated`);
}
```

### 4.3 Rollback Procedure
1. **Pre-migration**: Export affected documents to backup collection
2. **During migration**: Log progress to `migration_status` collection
3. **On failure**: 
   - Stop migration script
   - Restore from backup collection
   - Notify engineering team via PagerDuty
4. **Post-migration**: Verify sample documents, monitor error rates for 24h

## 5. Performance Optimization Guidelines

### 5.1 Query Best Practices
✅ **DO**:
- Use composite indexes for multi-field queries (define in `firestore.indexes.json`)
- Limit results with `limit()` and paginate with cursors
- Select only needed fields with `select()` to reduce bandwidth
- Use `array-contains` for category filtering (pre-indexed)

❌ **AVOID**:
- `!=` queries (require client-side filtering)
- Multiple `array-contains` in same query (not supported)
- Unbounded collection reads (always use `limit`)
- Client-side sorting of large result sets (sort in query)

### 5.2 Denormalization Strategy
| Field | Source Collection | Denormalized To | Update Trigger |
|-------|------------------|-----------------|---------------|
| `professionalName` | `users.displayName` | `bookings.professionalName` | User profile update |
| `societyName` | `societies.name` | `users.societyName` | Society update |
| `lastMessagePreview` | `messages.text` | `conversations.lastMessage` | New message created |
| `averageRating` | `reviews.rating` | `users.stats.averageRating` | New review submitted |

**Update Pattern for Denormalized Fields**:
```typescript
// Use Firestore transactions to ensure consistency
async function updateProfessionalName(userId: string, newName: string): Promise<void> {
  const batch = db.batch();
  
  // 1. Update user profile
  const userRef = db.collection('users').doc(userId);
  batch.update(userRef, { displayName: newName, updatedAt: FieldValue.serverTimestamp() });
  
  // 2. Update denormalized references in active bookings
  const bookingsSnap = await db.collection('bookings')
    .where('professionalId', '==', userId)
    .where('status', 'in', ['requested', 'confirmed', 'in_progress'])
    .get();
  
  for (const bookingDoc of bookingsSnap.docs) {
    batch.update(bookingDoc.ref, { professionalName: newName });
  }
  
  await batch.commit();
}
```

### 5.3 Caching Strategy
```typescript
// Client: TanStack Query configuration for Firestore data
const firestoreQueryOptions = {
  staleTime: 5 * 60 * 1000,    // 5 minutes: balance read freshness vs. cost
  cacheTime: 30 * 60 * 1000,   // 30 minutes: keep in memory for navigation
  refetchOnMount: false,       // Don't refetch on component remount
  refetchOnWindowFocus: false, // Avoid unnecessary refetches
  
  // Custom fetcher with offline support
  queryFn: async ({ queryKey }) => {
    const [collection, filters] = queryKey;
    const q = buildFirestoreQuery(collection, filters);
    
    // Try cache first (offline persistence)
    const cached = await getDocsFromCache(q);
    if (cached) return cached;
    
    // Fallback to network
    const snapshot = await getDocs(q);
    return snapshot.docs.map(doc => ({ id: doc.id, ...doc.data() }));
  }
};
```
