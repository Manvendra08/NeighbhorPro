# Phase 8.1: Define Chunking Strategy and Measure Bundle Impact

## Objective

Define practical chunk boundaries in `vite.config.ts` to reduce bundle size and warnings, then measure and document the impact. This closes PERF-01 (bundle warnings reduction).

## Problem Analysis

**Current State:**
- Main bundle is large and likely exceeds recommended size thresholds
- Vite produces warnings during build (e.g., "assets can affect page performance...")
- No chunking strategy is defined in vite.config.ts
- Large modules (e.g., Firebase SDK, component libraries) are bundled together

**Audit Finding:**
```
PERF-01: status: unsatisfied
Evidence: "No practical chunk boundary strategy is defined in vite config; 
no phase 5 verification artifacts."
```

## Success Criteria

- ✅ Chunking strategy is defined with clear boundary rationale
- ✅ vite.config.ts includes rollupOptions with optimized chunk configuration
- ✅ Bundle warnings are reduced by >50% (or eliminated)
- ✅ Main bundle size is measured before and after
- ✅ Vendor chunks are separate from app code
- ✅ Build still succeeds with no new errors
- ✅ CHUNKING-STRATEGY.md documents approach, measurements, and recommendations

<task id="8.1.2">
**Design chunking strategy**

1. Define chunk boundaries:
   - **Vendor chunk:** All node_modules (React, Firebase, UI libraries)
   - **Utils chunk:** Utilities, helpers, constants (likely reused)
   - **Components chunk:** Reusable components (if >100KB total)
   - **Pages chunk:** If any page is particularly large

2. Example vite.config.ts rollupOptions:
   ```typescript
   rollupOptions: {
     output: {
       manualChunks: {
         vendor: ['react', 'react-dom', 'firebase/app', 'firebase/firestore', ...],
         utils: ['src/utils/', 'src/lib/', 'src/constants/'],
         components: ['src/components/'],
       },
     },
   }
   ```

3. Rationale for each chunk:
   - Vendor: third-party code that changes infrequently
   - Utils: code reused across app (caching benefits)
   - Components: if large, defer loading to improve main bundle load

4. Document strategy in CHUNKING-STRATEGY.md

**Acceptance:**
- Chunking strategy defined with clear boundaries
- Rationale documented
- Configuration drafted for vite.config.ts
</task>

<task id="8.1.3">
**Implement chunking in vite.config.ts**

1. Open `vite.config.ts`
2. Locate or create `rollupOptions` in build config
3. Add manualChunks configuration:
   ```typescript
   export default defineConfig({
     build: {
       rollupOptions: {
         output: {
           manualChunks(id) {
             // Vendor chunk: all node_modules
             if (id.includes('node_modules')) {
               // Split Firebase into separate chunk
               if (id.includes('firebase')) {
                 return 'firebase-vendor';
               }
               return 'vendor';
             }
             
             // Utils chunk: utilities and constants
             if (id.includes('/src/utils/') || id.includes('/src/constants/')) {
               return 'utils';
             }
             
             // Components chunk: reusable components
             if (id.includes('/src/components/') && !id.includes('/src/pages/')) {
               return 'components';
             }
           },
         },
       },
     },
   });
   ```

4. Ensure:
   - Syntax is correct (TypeScript compilation)
   - No duplicate chunk names
   - All large modules are assigned

**Acceptance:**
- vite.config.ts updated and compiles
- manualChunks configuration is in place
- No TypeScript errors
</task>
