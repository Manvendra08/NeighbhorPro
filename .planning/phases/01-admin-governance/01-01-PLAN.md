## Objective

Harden admin role escalation confirmations and verification review audit capture to prevent accidental privilege elevation and ensure all review actions have full traceability.

**Purpose:** Ensure ADMN-01 (confirmation gates) and ADMN-02 (reviewer metadata capture) are robust and cannot be bypassed.

**Output:** 
- Verification review actions always record reviewer ID, timestamp, and note text in audit log
- Role escalation to admin requires explicit confirmation (current window.prompt is insufficient)
- Admin cannot accidentally self-demote or demote sole remaining admin

  <name>Task 1: Create auditService.ts with structured metadata capture</name>
  <files>src/services/auditService.ts</files>
  <action>
Create new audit service that wraps logAudit() with strict metadata validation:

1. Export interface `AuditMetadata` with required fields:
   - action: string (e.g., "user.role_change", "verification.reviewed")
   - adminId: string (reviewer/actor UID)
   - adminName: string
   - details: string (free-form summary)
   - targetId: string | null
   - metadata: { [key: string]: any } (custom structured data)
     - For role changes: { oldRole, newRole, targetName }
     - For verification reviews: { verificationStatus, reviewNote, targetName }

2. Export function `captureAuditEvent(metadata: AuditMetadata)` that:
   - Validates all required fields are present and non-empty
   - Enforces adminId !== targetId for sensitive actions (role_change, user.disable)
   - Calls existing logAudit() with structured payload
   - Returns Promise<string> documentId

3. Export function `getAuditSchema()` that returns JSON schema for audit events (used for UI validation)

4. Tests: Verify that missing required fields throw error, verify that self-actions are blocked for sensitive operations

Reference existing logAudit() signature but layer validation and metadata structuring on top.
