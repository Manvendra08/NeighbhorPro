<task id="9.1.2">
**Implement server-side filtering in firestoreService**

1. Analyze `listProfessionals()` in firestoreService.ts:
   - Identify where Firestore query is built
   - Add filters to query:
     ```typescript
     let query = collection(db, 'professionals');
     
     if (filters.category) {
       query = query.where('category', '==', filters.category);
     }
     if (filters.minDistance !== undefined) {
       query = query.where('distance', '<=', filters.minDistance);
     }
     if (filters.availability) {
       query = query.where('availability', '==', filters.availability);
     }
     ```

2. Update function signature:
   ```typescript
   export async function listProfessionals(filters?: {
     category?: string;
     distance?: number;
     availability?: string;
     // ... other filters
   }): Promise<Professional[]> { ... }
   ```

3. Ensure:
   - Mirror-lag fallback still works (no breaking changes)
   - Query indexes are configured in Firestore if needed
   - Filters are applied before `.limit()` for efficiency

4. Add unit tests:
   - Query with filters applied correctly
   - Query with no filters returns all
   - Invalid filter values are handled gracefully

**Acceptance:**
- firestoreService.listProfessionals() accepts filter parameters
- Firestore query includes where clauses
- No regressions in existing functionality
- Tests pass
</task>
