# Phase 6.1: Add Service-Layer Duplicate Payout Guard

## Objective

Implement a service-layer duplicate payout prevention mechanism in `coinService.requestPayout()` to close WLET-04 unsatisfied requirement. Currently, duplicate prevention is UI-only; this adds transaction-level enforcement.

## Problem Analysis

**Current State:**
- `coinService.requestPayout()` accepts new payout requests without checking for pending payouts
- Duplicate prevention only exists in wallet UI state management
- If malicious user or race condition bypasses UI, duplicate submissions can occur
- **Risk:** Multiple payout requests approved and processed, leading to duplicate payouts

**Audit Finding:**
```
WLET-04 status: unsatisfied
Evidence: "Duplicate prevention is enforced in UI state only; 
service-level payout request path lacks pending-check guard."
```

## Success Criteria

- ✅ `requestPayout()` queries for existing pending payouts before allowing new request
- ✅ Returns 409 Conflict error if pending payout already exists for user
- ✅ Error includes clear message: "A payout request is already pending. Please wait for processing or cancel existing request."
- ✅ Guard works correctly: users cannot submit duplicate while one is pending
- ✅ Users can modify pending request (e.g., update amount) if service allows, or must cancel first
- ✅ All test cases pass (normal flow, duplicate attempt, cancel then new request, etc.)

<task id="6.1.2">
**Implement pending payout check in requestPayout()**

1. Add query before payout creation:
   ```typescript
   // Pseudo-code pattern:
   const existingPending = await db
     .collection('users').doc(userId)
     .collection('payouts')
     .where('status', '==', 'pending')
     .limit(1)
     .get();
   
   if (!existingPending.empty) {
     throw new Error('PENDING_PAYOUT_EXISTS', {
       statusCode: 409,
       message: 'A payout request is already pending...'
     });
   }
   ```

2. Place guard **before** any payout document write
3. Add logging: `logger.info('Duplicate payout prevented for user ${userId}')`
4. Add telemetry: event name `wallet_duplicate_payout_blocked`
5. Ensure error propagates correctly to caller (coinService.test.ts validates)

**Acceptance:**
- Guard implemented and compiled without errors
- Error thrown at correct point (before write)
- Logging + telemetry capture duplicate attempts
</task>
